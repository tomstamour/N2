# orchestrator_trigger_rules.txt — THE TRADE GATE.
#
# This file IS the gate. Orchestrator5.4.py holds no thresholds and no rules of
# its own: every cut that decides whether a press release becomes a trade is on
# one of the rule lines below. Add a rule, retune a threshold, delete a rule —
# edit here, restart O5.4, done. No Python edit.
#
# Read by  : orchestrator5/Orchestrator5.4.py
#            _load_trigger_rules()  ->  _evaluate_trigger()
#
# !!!! THIS FILE NOW REQUIRES 5.4.  Orchestrator5.3.py CANNOT LOAD IT.  2026-09-24
#   The XgbSolo rule at the bottom names `ge50_m3` (model-3), a field 5.3 has never
#   heard of — and 5.4 no longer knows 5.3's `ge50_m2`, nor its DeBERTa / TradeHero /
#   FinancialB fields. An unknown field is a HARD FAIL with no fallback gate, in
#   BOTH directions — recognise these, they are not a corrupt file:
#       5.3 on this file   : orchestrator_trigger_rules.txt:<line>: unknown field
#                            'ge50_m3' — ... — refusing to start
#       5.4 on 5.3's file  : orchestrator_trigger_rules.txt:<line>: unknown field
#                            'ge50_m2' — did you mean: ge50_m3, ge50_m3FT, ge35_m3?
#   ROLLBACK TO 5.3 IS ONE LINE: put back
#       XgbSolo:     FineClass not in __CLASSIFIER_DEAD__ AND ge50_m2 >= 0.70
#   (or copy orchestrator_trigger_rules.5.3.txt — 5.3's exact file — over this one)
#   and start 5.3. Nothing else in here is 5.4-only.
#   5.2 can load neither version.
#
# WHEN READ: ONCE, at startup, before any model is loaded.
#   !! Editing this file does NOT change a process that is already running.
#      A running O5.4 keeps the gate it started with until you restart it.
#      The `[Gate] ACTIVE` block in logs/Orchestrator5.4_YYYY_MM_DD.log is the
#      authoritative record of what a given process actually holds — the daily
#      TSV header does not change with the gate, so the log is the only place
#      that answers "which gate ran today?".
#   Dry-run a change in ~1 second, without loading a model or opening a socket:
#      /home/tom/venv/bin/python Orchestrator5.4.py --check-rules
#   Exit 0 means the gate echoed is exactly the gate O5.4 would run.
#
# !! A RULE ON AN XGBoost-LEG FIELD MAKES STEP-1b WAIT FOR THE LEG.  2026-09-24
#   Naming any se_* / q80_* / ge*_m3* / TimeToOpen field in ANY rule sets
#   _gate_needs_xgb: the gate cannot be evaluated until model-3's INT8 headline
#   embedding and the booster(s) the rules name have run. Under 5.3 / model-2 that
#   cost ~870 ms on EVERY trade decision; model-3 costs ~25-35 ms of model time per
#   PR, and only the booster(s) a rule names run before the send.
#   MEASURED 2026-09-24 (bench/reports/O54_latency_2026-09-24_1426.md): the worst PR
#   of any of the 16 biggest historical bursts reached the clerk 168 ms after
#   reception, a lone PR ~60 ms. (5.3 live with model-2: median 983 ms, max 7.5 s.)
#   The arm is issued at reception either way; it is the trade DECISION that waits.
#   It also escalates the universe dependency: with the leg gating, a universe TSV
#   that predates daily_universe_pipeline-3 becomes a STARTUP HARD FAIL rather
#   than `Xgb_status=disabled_universe` with trading carrying on regardless.
#   --check-rules prints which mode is in force on its last line, and startup logs
#   a WARNING naming the offending field(s).
#
# ON ERROR : O5.4 REFUSES TO START. A missing file, an empty file, an unknown
#   field, a bad operator, an unparseable number, a duplicate rule name — any
#   of them is a hard failure with a `file:line:` message. There is deliberately
#   NO fallback gate and NO skip-the-bad-line: a trading process must never run
#   a gate nobody wrote, and a one-character typo must never silently delete a
#   branch while the tape still looks alive. Use --check-rules before a restart.
#   !! A misspelled FIELD NAME is caught here, with a did-you-mean. A misspelled
#      class VALUE is not — see the FineClass note in the Fields section.
# ==============================================================================
#
# ── Format ────────────────────────────────────────────────────────────────────
#   One rule per line, in one of TWO forms:
#       <RuleName>:         <field> <op> <value> AND ...    an ordinary rule
#       REQUIRE <RuleName>: <field> <op> <value> AND ...    a PRECONDITION
#
#   Ordinary rules are OR-ed — a row trades when ANY ONE of them all-holds.
#   REQUIRE lines are AND-ed — EVERY one must hold, or nothing trades at all.
#   Conditions are AND-ed within either kind of line.
#
#       the gate = (every REQUIRE line holds) AND (any ordinary rule fires)
#
#   There is no OR inside a line and no parentheses. To express an OR, write a
#   second rule; that is what rules are.
#
#   RuleName  letters and digits, starting with a letter. Must be unique —
#             ordinary and REQUIRE rules share ONE name space, because both
#             print as a group in the TSV Trigger cell.
#             NO UNDERSCORE — fired rule names are joined with '_' into the TSV
#             ClerkSentiment cell, so an underscore in a name would make that
#             cell ambiguous. 'BAD', 'skipped' and 'REQUIRE' are reserved.
#             The name is yours and it lands in ClerkSentiment, so name a rule
#             for what it means, not for the model it reads.
#   AND       case-insensitive, must be surrounded by spaces.
#   REQUIRE   case-insensitive, separated from the name by whitespace.
#   #         starts a comment, anywhere on a line. Blank lines are ignored.
#
# ── Operators ─────────────────────────────────────────────────────────────────
#   >=  <=  >  <  ==  !=  in  not in
#   Numeric fields take the six comparisons. `in` / `not in` are REJECTED there —
#     they are set membership over STRING values (write a range, or a 2nd rule).
#   String fields take == , != , in and not in , all CASE-INSENSITIVE
#     (FineClass == earnings_results matches Earnings_Results).
#
#   `in` / `not in` take a COMMA-SEPARATED list. Braces are optional on input and
#   are how the [Gate] ACTIVE echo prints one back, so an echoed rule can be
#   pasted straight into this file:
#       FineClass in MA, Partnership, Patent_IP        a whitelist
#       FineClass not in Reverse_Split                 a blacklist
#   A list is REJECTED at load if an element contains a SPACE (almost always a
#   missing comma), if a value repeats, or if an element is empty (a doubled or
#   trailing ','). Every one of those silently SHRINKS the set, which is exactly
#   what the hard-fail policy exists to stop.
#
# ── REQUIRE: preconditions ────────────────────────────────────────────────────
#   A `REQUIRE <Name>: ...` line NEVER FIRES ANYTHING. It only PERMITS. Every
#   REQUIRE line must hold before any ordinary rule is allowed to trade, so one
#   of them constrains the WHOLE gate at once — which is the point: without it,
#   a constraint you want on every rule has to be copy-pasted onto every line,
#   and silently missed off the next rule somebody adds.
#
#   Because a REQUIRE rule permits rather than fires:
#     - Its name NEVER reaches ClerkSentiment. A row it blocked reads `BAD`,
#       like any other non-fire. The Trigger cell is what tells them apart.
#     - Its Trigger group prints ALLOW / BLOCK, not YES / NO. Count blocked rows
#       with:   grep -c ':BLOCK\[' tables/news_output_*.tsv
#     - !! A `CORE:YES` GROUP CAN NOW SIT IN A CELL WHOSE VERDICT IS `NO`. The
#       rule held; a precondition blocked it. Read the LEADING YES/NO for what
#       the row did and the groups for why. Anything that counted fires by
#       grepping `:YES` is wrong as of 2026-08-17.
#     - A file with ONLY REQUIRE lines is a hard error: nothing could ever fire.
#
#   !! REQUIRE FAILS CLOSED. A None on a REQUIRE condition fails it like any
#      other, and that closes the entire gate rather than one branch — so a dead
#      scorer behind a precondition stops ALL trading. That is deliberate, and it
#      makes whatever a REQUIRE line reads a single point of failure. The
#      BLOCKED-BY-MISSING-SCORE-ONLY alarm below is what makes it visible.
#
# ── Missing scores ────────────────────────────────────────────────────────────
#   A score can be absent: a model raised, a future timed out, or the symbol is
#   not in today's universe TSV. Such a value is None, and None ALWAYS FAILS its
#   condition — it never passes, never raises, never wraps around. The Trigger
#   cell prints `<field>:MISSING` for it.
#
#   `EarningScore:NA` is a DIFFERENT thing and is not a fault: the earnings
#   scorer is skipped on purpose for every PR that is not an Earnings_Results
#   (~81% of rows), so a blank EarningScore means "not an earnings PR", never
#   "scored 0". NA is why the one row where the scorer actually DIED is still
#   visible instead of buried under 300 innocent ones.
#
#   When every evaluable condition of a rule passed and only a MISSING score
#   stood between the row and a fire, O5.4 logs at WARNING:
#       [Gate] <SYM> BLOCKED BY MISSING SCORE ONLY — ...
#   That is the dead-scorer alarm. A rule with ONE condition (see the solo rules
#   below) makes it very loud by design: a dead model there removes an entire
#   branch, and a gate that quietly stopped firing looks exactly like a quiet
#   news day. Grep logs/ for that string.
#
#   !! A None on a REQUIRE condition is the LOUDEST case in this file, because it
#      closes the whole gate rather than one branch: the alarm then fires on
#      EVERY row until the scorer is fixed. That volume IS the signal. With the
#      ClassWhitelist line below, a dead PR classifier stops all trading, and
#      this WARNING is the only thing that distinguishes that from a quiet day.
#

# !! 2026-09-21 — XgbSolo IS THE ONE RULE EXEMPT FROM THE CLASS WHITELIST.
#    It fires on ANY catalyst class: Offering_Financing, Other, Product_Launch,
#    Business_Update, Legal — anything. That is deliberate (operator, measured
#    above: 38.0% over all classes vs 37.7% whitelisted). The justification is
#    that this rule is the only one whose model READS the class — FineClass is
#    one of model-2's 25 features — so it is not blind to catalyst type the way
#    the five sentiment rules are, which is why they keep the whitelist.
#
# !! `FineClass not in __CLASSIFIER_DEAD__` IS A LIVENESS GUARD, NOT A FILTER.
#    __CLASSIFIER_DEAD__ is not a real class, so EVERY real class passes it. Its
#    only job is to fail when FineClass is None, i.e. when PrClassifier died or
#    its future timed out. Without it this rule would be the one thing still
#    trading through a classifier outage — on a feature vector with that very
#    feature NaN. With it, the gate still fails closed everywhere, and
#    BLOCKED BY MISSING SCORE ONLY still means what it has always meant.
#    ⚠ Do NOT "tidy" this condition away, and do NOT rename the sentinel to
#      something that could ever collide with a real PrClassifier class.
XgbSolo:     FineClass not in __CLASSIFIER_DEAD__ AND ge50_m3 >= 0.646
