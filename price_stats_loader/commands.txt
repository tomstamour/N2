# model-2 CLASSIFIER CALIBRATION -- turn proba_clf_ge20/35/50 into real probabilities.
# STATS ONLY: no gate, no rule line, nothing under orchestrator5/ touched, no retrain.
# Report: statsByClaude/2026-09-20_XGB_model2_calibration.md
#
# WHY: those three columns were trained with scale_pos_weight 4.18/8.33/12.53, which
# multiplies the modelled ODDS by that weight. They are rank scores wearing probability
# clothing -- all three score NEGATIVE Brier skill (worse than always answering the base
# rate). See 2026-09-20_XGB_model2_deep_analysis.md §4.
#
# WHAT IT DOES: reads only the score columns that already exist plus the outcome column
# beside them. Sorts by score, measures what fraction of each region actually hit its
# threshold, fits a curve. Five monotone methods compared -- raw / prior (the free
# p/(p+(1-p)*w)) / platt / beta / isotonic. ~5s, no pipeline, no new data.
#
# ⚠ EVERY HEADLINE NUMBER IS OUT OF FOLD (fit on 20 sessions, score the held-out 5,
# rotate). A curve fitted on all 1380 rows and graded on those same rows looks superb
# whether or not it works -- isotonic is the proof: best in-sample on all three columns,
# and it gives most of it back out of fold.
/home/tom/venv/bin/python calibrate_model2_clf.py

# ANSWER: use `platt` (2 params/column, saved in model2_calibration_params.json). The
# free `prior` formula OVER-corrects by construction -- it divides by the full weight
# though XGBoost regularisation already pulled the odds back -- landing 14%/21%/32% below
# the true base rate, the miss growing with the weight. platt matches the base rate on
# all three and halves ECE. Calibration changes NO ranking decision: all five methods are
# monotone, and the control table shows AUC shift 0.000000 for platt/beta/prior.
# isotonic is the one exception (pooling creates ties, costs 0.008-0.015 AUC) -- don't use it.
#
# Controls: 11/11 reproduction of the deep analysis §4 Brier values + row/session/positive
# counts; per-fold AUC monotonicity gate. Exits NON-ZERO on either failure (verified by
# corrupting a score column). Artifacts beside the report:
#   model2_calibration_params.json       -- fitted params, all 3 columns, all 4 methods
#   model2_calibration_methods.tsv       -- full metric grid (Brier/skill/ECE/MCE/logloss)
#   model2_calibration_reliability.tsv   -- per-bin observed vs predicted

#
# ANSWER for proba_clf_ge50: >= 0.70, equivalently the top ~10%. 150 fires / 25 sessions
# (6.0/day), 38 TP + 112 FP, precision 25.3%, 2.65x base rate, recall 28.8%.
#
# ⚠ THREE TRAPS the script exists to stop, all of them live in this data:
#  1. The in-sample optimum is a MIRAGE. Searching the fold returns 0.83 at 30.6%; the
#     same search on half the data overstated itself by ~6 points on average (one arm by
#     10.3). Never quote a searched-for precision as the expected hit rate.
#  2. Precision PLATEAUS at 0.70-0.80 (25.3/25.0/24.6/25.0%) while recall falls 28.8%
#     -> 6.8%. Stand on the LOWEST cut of the plateau, not the highest.
#  3. An absolute cut is not a stable workload. Held at top-10% precision was 27.7% vs
#     27.4% across the two date halves; at top-5% it swung 30.3% vs 16.2%. Set cuts from
#     a measured quantile -- the same advice in Orchestrator5.3.py:1583.
#  Also: 0.90 fires 9 times and hits 0. --min-fires flags cuts too thin to measure.
#
# Controls: 5/5 (confusion sums to 1380 at every cut, fire count non-increasing,
# 132 positives, 25 sessions). Exits non-zero on failure. Artifact:
#   model2_ge50_threshold_sweep.tsv -- the full grid incl. per-half precision and swing
