highOfDay_addON_1.0.py — 2026-06-01
1. ArrivalTime values are treated as UTC-4 (EDT); market close threshold is 16:00 ET (was incorrectly 20:00 UTC in the base version).
2. For pre-market / intraday arrivals (< 16:00 ET), fetches the daily high of the same trading day only.
3. For after-market arrivals (>= 16:00 ET), fetches both the same day and the next trading day via the new get_target_dates() function.
4. DailyHigh(%) is computed independently for each fetched day; the higher value is written to the output along with its corresponding DailyHigh($).
5. Caching and pacing are unchanged: each unique (symbol, date) pair triggers one IBKR request and one pacing sleep, so after-market rows may incur two sleeps if both dates are uncached.

fromPR_HighOfDay_addOn.py — 2026-07-06
1. New add-on: measures the highest price reached AFTER the PR "Created" time (HH:MM:SS.mmm ET, from createdTime_AddOn.py), as a % of the price just before the PR (close of the last 1-min bar before Created) — unlike DailyHigh(%) which is vs. the previous daily close.
2. Window: Created -> 20:00 ET of the target session; created before 16:00 ET on a trading day = same day, otherwise (after close / weekend / holiday) rolls to the next trading session (in-between after-hours included).
3. Extended hours included (useRTH=False), 1-min TRADES bars, durationStr='2 D' so the pre-Created baseline bar exists even for 04:00 pre-market PRs and Friday-evening -> Monday rolls.
4. New columns: fromPR_High(%) and fromPR_HighTime(m:s) (elapsed MM:SS from Created to the high's bar, minutes unbounded, clamped at 00:00).
5. Same scaffolding as highOfDay_addON.py (clientId 7, reconnects, 'ok'/'failure'/'skip' status, consecutive-failure HMDS abort, (symbol, created) cache). Output: <input_stem>_fromPRhigh.tsv.
6. --timeout/-t flag (default 180s): 1-min extended-hours queries on illiquid small caps take 80-150s+ per symbol when the live stack (clerk/daily-board/scanner) shares the Gateway — run the full backfill when those are idle.

fromPR_HighOfDay_addOn.py — 2026-07-26 (baseline fix)
1. BUGFIX: the baseline was the close of the 1-min bar CONTAINING the PR, not the bar before it. The old test `start < created_dt` accepts the PR's own bar (09:00:00 < 09:00:05.467), so the denominator already priced the news in. Baseline is now the last bar ending at or before the PR minute (`start < created_dt.replace(second=0, microsecond=0)`). The high search still includes the PR's bar — that part was correct.
2. Impact is the price move inside the PR's own minute, so the error is biased AGAINST the very reaction the metric measures: positive catalysts were understated, PRs that gapped down inside their minute were overstated. Verified 2026-07-26 on paper GW: ZCMD 2026-07-23 373.32 -> 200.49 (offering PR, -36.5% inside the PR minute); UPC 2026-06-26 371.00 -> 536.49; VIVK 2026-07-21 339.94 -> 478.18; TNMG 167.03 unchanged (no move inside its PR minute).
3. Side effect: the `baseline is None` -> 'skip' guard can now actually fire. Previously the PR-minute bar always populated `baseline`, so rows with no genuine pre-PR price were silently scored 'ok' off a post-news denominator.
4. Existing fromPR_High(%) values in the PRstats corpus predate this fix and are wrong; re-score by clearing the column (a plain --only-missing run will NOT touch rows that already have a value).
